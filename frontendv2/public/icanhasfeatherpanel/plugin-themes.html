Plugin Themes & UI Packs

Extend FeatherPanel appearance and layout at runtime — no panel pnpm build when installing a pack.

Theme packs

Ship Frontend/theme.json (+ optional theme.css). Users select packs in Preferences → Appearance.

API: GET /api/system/plugin-themes, CSS: GET /api/system/plugin-theme-css?id=plugin:themeId

Schema: plugin-theme.schema.json

{
  "id": "ocean",
  "name": "Ocean",
  "tokens": {
    "light": { "primary": "199 89% 48%", "background": "210 40% 98%" },
    "dark": { "primary": "199 89% 48%", "background": "222 47% 7%" }
  },
  "css": "theme.css"
}

Overrides (surgical)

Frontend/overrides.json — hide / replace / actions on named slots.

API: GET /api/system/plugin-overrides

Schema: plugin-overrides.schema.json

Shell slots: shell.sidebar, shell.navbar, shell.page-header, shell.main, shell.background

UI packs (full makeover)

Frontend/ui.json — shell replace, page replace, hide list, toolbar actions. One active pack at a time.

API: GET /api/system/plugin-ui-packs

Schema: plugin-ui-pack.schema.json

{
  "id": "glass",
  "name": "Glass Dashboard",
  "theme": "ocean",
  "shell": {
    "replace": {
      "shell.sidebar": { "component": "Components/Sidebar.html" }
    }
  },
  "pages": [
    { "match": "/dashboard", "replace": { "remote": "dist/Dashboard.js" } }
  ],
  "hide": [],
  "actions": []
}

Host bridge

Panel exposes window.FeatherPanel v2 — see Power SDK for events, actions, modals, search, shortcuts.

Iframe protocol (same-origin):

  • featherpanel-ready → host replies with featherpanel-theme
  • featherpanel-navigate { path }
  • featherpanel-toast { message, level }
  • featherpanel-bus — event/action bridge

React remotes

Point a slot remote at a prebundled ESM that default-exports a React component. React is provided by the host. No panel rebuild when installing the plugin.

Dev templates

Admin → Developer → Plugins → Create: choose Theme pack or UI pack.
